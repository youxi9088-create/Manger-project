# OpenClaw UI 优化设计 Spec

## 1. 产品本质

**OpenClaw** 是一个面向中大型团队研发的 AI 驱动型项目协作平台。它不是传统意义上的「项目管理工具」，而是把 AI Agent、工作流、会议分析、需求跟踪、日报计划等能力整合进一个统一工作台。用户通过它让 AI 辅助完成项目信息聚合、任务拆解、会议纪要和风险分析等高频工作。

产品核心卖点：**用 AI 降低项目管理中的信息整理与沟通成本**，让项目经理和研发团队把精力放在判断与执行上，而不是在多个工具之间搬运信息。

## 2. 目标受众与使用场景

- **主要用户**：项目经理、产品经理、研发组长、技术负责人
- **次要用户**：普通研发成员、管理层（查看项目健康度）
- **典型场景**：
  - 早晨打开 Dashboard，快速了解今日会议、待办、项目风险
  - 在 Daily 页面用 AI 生成今日计划，并同步会议纪要中的待办
  - 在 Projects 列表查看多个项目进度、阶段、风险
  - 进入 Project Detail 查看需求、任务、成员、交付、日志
  - 通过 Workflow 触发 AIHub 工作流，获取项目综合分析
  - 使用 Meeting Assistant 查看录音、转写、纪要、待办
  - 与 Hermes Agent 对话，让 AI 执行复杂查询或操作

## 3. 核心信息与主要页面板块

需要设计的页面/模块（按优先级排序）：

1. **Dashboard / 今日工作驾驶舱**（首页）
   - 今日关注（会议提醒、逾期任务、待分析聊天记录）
   - 今日会议列表
   - 今日任务列表
   - 项目健康度卡片（进度条、阶段、风险）
   - 快捷操作按钮

2. **Daily / 日报计划**
   - 目标/背景输入区
   - AI 生成任务按钮
   - 从会议/聊天记录导入
   - 历史未完成任务提示
   - 可筛选任务列表（状态、优先级、截止时间）

3. **Projects / 项目列表**
   - 统计卡片（总数、执行中、招募中、高风险）
   - 搜索 + 阶段筛选
   - 项目卡片网格（进度、阶段标签、截止日期倒计时、同步状态）

4. **Project Detail / 项目详情**
   - 顶部：项目名称、同步操作、阶段标签、风险指示
   - Tab：概览、需求、任务、成员、交付、日志
   - 概览页：关键指标、知识库摘要、阶段时间线、行动建议

5. **Workflow / 工作流**
   - 触发面板（proid + ask）
   - 结果卡片（Markdown 渲染）
   - 历史记录 + 项目信息 Tab

6. **Meeting Assistant / 会议助手**
   - 录音列表 + 状态
   - 转写 / 下载音频 / 重新生成纪要
   - 模态框：深度分析、摘要、待办、原文
   - 同步待办到日报

7. **Agent Chat / Hermes Agent 对话**
   - 会话侧边栏
   - 消息气泡流
   - 工具调用折叠展示

8. **Quick Search / 轻量 AI 搜索**
   - 会话列表
   - 流式回答展示

9. **Company / 团队**
   - 员工目录（可搜索网格、详情弹窗）
   - 看板 + 工作周期排期表

10. **Tools / 工具台**
    - 工具卡片网格入口

## 4. 情感基调与气质关键词

- **专业可信**：这是企业级工具，用户会把项目核心数据放进来，视觉必须稳重、不轻浮。
- **智能但不冰冷**：AI 是产品核心，但不要让界面看起来像「实验室工具」。要有温度。
- **高效清晰**：信息密度高，但不能乱。层级必须清晰，一眼能找到重点。
- **现代克制**：避免 2020-era 的圆角大阴影卡片 + 左彩色 border 的 slop 组合。
- **暗色主场**：当前 openclaw 默认 dark mode，优化应保持暗色主调，但可以探索更精致的暗色层次。

关键词：**沉静、精密、可信、智能、有秩序**

## 5. 输出格式与尺寸

- **格式**：纯 HTML/CSS 单文件或可点击多页原型（根据方向决定）
- **主尺寸**：桌面端 1440×900，关键页面额外做 1920×1080 展示
- **交互形式**：
  - 至少包含 Dashboard、Projects、Project Detail、Daily、Meeting Assistant 五个核心页面的可切换展示
  - 状态变化：hover、active、选中、loading、空态、错误态
- **字体**：中文优先使用系统字体栈（PingFang SC / Hiragino Sans GB / Microsoft YaHei），英文/数字可用有特点的 display font 作为点缀
- **色彩**：暗色主调，可探索一种主品牌色作为 accent（当前代码里接近紫/靛蓝，但优化方向不局限于此）

## 6. 已知约束与禁忌

- 没有品牌 logo 源文件，没有 VI 规范，没有 Figma 源文件
- 没有参考风格图（用户明确说没有）
- 当前系统默认 dark mode，优化以暗色为主
- 中文 UI，需要注意中文排印细节（引号用「」、行高、字重）
- 数据密集型界面，避免过度装饰
- 不要为了 PPT 效果而牺牲信息密度

## 7. 图片素材策略

按 huashu-design Phase 3.5 判断：

- 这是一个 **工具 / 数据 / SaaS 型产品**，不是内容型产品
- 图片不是内容必需的，主要信息由文字、数字、状态、图表承载
- **策略**：
  - 不使用装饰性 stock photo
  - 不使用 SVG 手绘人物/场景
  - 图标使用 Lucide 风格图标或简洁几何图标
  - 如需氛围元素，使用极淡的抽象纹理/渐变（opacity ≤ 0.08）或不使用
  - 保留诚实 placeholder 给未来品牌插画位置

## 8. 设计方向生成规则

本次进入 huashu-design Fallback 模式，三个方向独立并行：

- **方向 A · 秒数轮盘**：当前秒数 45，计算 45 % 20 + 1 = **6**。从网页 20 种风格库中取第 6 号风格，严格按其视觉 DNA 实现。若该风格还原度不足，须诚实标注降级部分。
- **方向 B · 现实参照**：选择世界上最适合 openclaw 这类 AI 协作工具的顶级产品作为参照（如 Linear、Raycast、Claude、Notion），先拆解其设计语言，再迁移到 openclaw 内容上。
- **方向 C · 最佳设计师**：假设预算无上限，由世界顶级设计工作室（如 Pentagram、Stripe 设计团队、Linear 设计团队、原研哉等）为 openclaw 定制设计。

三个方向使用同一份 spec、同一套真实页面结构，只换设计逻辑，方便横向对比。
