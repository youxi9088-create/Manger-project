## 修复 Agent 工具调用全部失败 Bug（21:50-22:00）

### 问题
PM Agent 派发给 Exec Agent 的任务（如 `bad371f8-a2c8-4082-824b-3dfc74f4b7a1`，"分析最近的 IM 聊天记录，提取关键决策和待办事项"）工具调用全部失败。Exec Agent 循环了 20 次（maxIterations 上限），每次 `query_chat_records` 的 result 都是 null。

### 根因
`agent-tools-query.ts` 中 `query_chat_records` 工具的 SQL 使用了错误的列名：
- `send_time`（错误）→ 表中实际为 `timestamp`
- `msg_type`（错误）→ 表中实际为 `message_type`

这导致 SQL 执行报错，工具返回 null，Exec Agent 无限重试相同的工具调用直到 20 轮上限。

### 修复
在 `agent-tools-query.ts` 中将 `send_time` → `timestamp`、`msg_type` → `message_type`，SELECT 和 WHERE/ORDER BY 子句均已修正。

### 查看任务结果的方式
1. **API 端点**：`GET http://localhost:3001/api/agent/tasks` 返回最近 50 条任务
2. **看板视图**：`GET http://localhost:3001/api/agent/tasks/kanban` 按 running/completed/pending 分组
3. **SQLite 直接查询**：`data/chat.db` → `agent_tasks` 表，字段包括 id, status, description, tool_calls(JSON), result, error, iterations
4. **前端**：看板页面会展示 Agent 任务时间线

## PM Agent 对话持久化（刷新保留）（22:10-22:30）

### 问题
PM Agent 对话页面（`/tools/agent`）刷新后所有聊天记录丢失。后端已完整保存消息到 SQLite（sessions + messages 表），但前端完全不从后端加载历史消息，只用 React `useState` 维护消息，刷新即丢。

### 根因分析
| 环节 | 状态 |
|------|------|
| 后端消息保存 | ✅ 每条用户/助手消息都通过 `db.createMessage()` 持久化 |
| 后端历史查询 API | ✅ `GET /api/sessions/:id` 返回会话 + 所有历史消息 |
| 前端会话列表持久化 | ⚠️ localStorage 只存 `{id, title, createdAt}`，不含消息 |
| 前端加载历史消息 | ❌ 完全缺失 |

### 修复（仅改 `packages/web/src/app/tools/agent/page.tsx`）
1. **会话初始化**：优先从 `GET /api/sessions` 拉取后端会话列表（过滤有消息的），降级用 localStorage
2. **activeId 变化时**：自动调用 `GET /api/sessions/:id` 加载历史消息
3. **消息格式适配**：新增 `dbMsgToChatMsg` 函数，将后端 `DbMessage`（含 JSON 解析后的 tool_calls）转为前端 `ChatMessage`（含 `ToolCallState[]`），同时兼容两种 tool_calls 格式（`params` vs `input`）
4. **删除会话**：同步调用 `DELETE /api/sessions/:id`
5. **发送消息后**：重新同步后端会话列表，更新标题等元数据
6. **加载指示**：新增 `loadingHistory` 状态和 History 图标加载动画
7. **切换会话**：不再 `setMessages([])`，由 useEffect 自动处理
