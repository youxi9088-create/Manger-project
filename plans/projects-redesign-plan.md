# 「我的项目」模块改造计划

> 目标：把当前「项目数据看板」改造成**AI 项目群经理（游浠）的作战室**：一眼看清所有项目健康度，能推进下一步行动，立项→需求→任务→交付→收尾全链路闭环。

---

## 一、当前问题诊断

### 1. 定位不清
- 页面叫「我的项目」，但**没有按当前用户过滤**（`mine` 参数未使用）。
- 「新建项目」按钮跳到「项目立项」页面，立项与项目是同一批数据，用户分不清草稿/正式项目。

### 2. 功能割裂
- 详情页 5 个 Tab（执行/规划/成员/任务/收尾）内容堆砌，缺少以「当前阶段该做什么」为主线的引导。
- 成员 Tab 只读，干系人却能增删，两套人员数据互相独立。
- 任务/冲刺计划生成后无法调整，且与需求/任务创建入口分离。
- 收尾 Tab 只做列表展示，没有真正的验收/归档闭环。

### 3. 数据闭环断裂
- 项目状态同步只认 `initiation_id`，但需求创建可只填 `project_id`，导致进度统计漏数据。
- `work_cycles` 与 `dev_tasks` 状态双向不同步，真实工时进度无法反映到项目状态。
- 任务状态变更不会即时触发项目同步，必须等定时任务或手动刷新。
- 手动阶段流转与自动同步可能互相覆盖。

### 4. 写操作严重不足
- 详情页无法编辑标题、截止日期、团队规模、风险等级、知识库路径等基础信息。
- 成员没有移除/改角色能力。
- 风险只展示不治理，没有修改 `risk_reason` 的入口。

### 5. 体验细节
- 详情页 1694 行单体文件，维护困难。
- 统计卡片基于当前页数据而非全量真实统计。
- 默认 Tab 不合理：draft/planning 阶段打开「执行」Tab 常为空。
- 无加载/错误边界。

---

## 二、改造愿景

### 2.1 用户视角
> 游浠打开「我的项目」，第一眼看到的是：
> - 我负责/参与的项目健康度总览
> - 今天必须处理的风险 / 逾期 / 即将到期项
> - 每个项目下一步该做什么、@谁、截止什么时候
> - 点进项目后，按项目当前阶段展示最相关的操作和数据

### 2.2 模块定位
- **列表页**：项目群总览 + 风险雷达 + 批量操作入口。
- **详情页**：单项目作战室，围绕生命周期展示数据，提供推进动作。
- **AI 面板**：读数据 → 给建议 → 生成草稿 → 用户确认后执行（stage1）。

## 三、新信息架构

### 3.1 项目列表页 `/projects`

#### 顶部
- **标题**：「项目作战室」或保留「我的项目」。
- **快捷操作**：
  - 「新建项目」→ 在当前页弹窗快速创建（调用 `/api/project-initiation`），创建后自动进入详情。
  - 「同步全部状态」→ 批量同步。
  - 「AI 风险扫描」→ 调用执行中枢/Agent，扫描所有项目风险并生成报告（stage1：先生成草稿，用户确认）。

#### 统计卡片（真实全量统计）
- 全部项目 / 我负责的项目 / 执行中 / 高风险 / 本周到期 / 已逾期
- 后端增加聚合接口或改造 `/api/projects` 返回 `stats`。

#### 筛选栏
- 搜索（标题/外部 ID）
- 阶段筛选
- 风险等级筛选
- 「只看我的」开关（传 `mine=true`）
- 排序：最近更新 / 截止日临近 / 风险等级

#### 项目卡片
每张卡片展示：
- 标题 + 外部 ID + 阶段 Badge
- 整体进度条 + 截止倒计时（逾期标红、3 天内标黄）
- 团队规模（当前/计划）
- 风险等级图标 + 同步新鲜度
- 最近 1-2 条「下一步行动建议」（可来自 AI 扫描或规则）
- 悬浮/展开快捷操作：同步、进入详情、生成同步消息

### 3.2 项目详情页 `/projects/[id]`

#### 头部
- 返回列表
- 项目标题、代号、VP、截止日期（可编辑）
- 当前阶段 Badge、健康度、风险等级（可编辑）
- 上次同步时间 + 「同步状态」按钮
- 根据当前阶段推荐的下一步操作按钮（如：提交审批 / 开始执行 / 生成冲刺计划 / 验收归档）

#### 内容区：6 个 Tab

| Tab | 定位 | 核心内容 |
|-----|------|----------|
| **概览** | 项目健康度与下一步 | 进度、阶段时间线、风险与阻塞、最近动态、AI 建议卡片 |
| **需求** | 需求全生命周期 | 需求列表、创建需求、AI 分析需求、AI 拆解任务、关联版本 |
| **任务** | 任务与冲刺 | 全部任务、2 周冲刺时间轴、分配/调整/更新状态 |
| **成员** | 项目团队 | 成员列表、添加/移除/修改角色、负载概览 |
| **版本** | 版本与目标 | 版本列表、目标管理、目标转需求 |
| **收尾** | 验收与归档 | 待收尾项、验收 checklist、归档操作 |

**知识库内容不再单独作为一个 Tab**，而是融入到「概览 / 规划 / 版本」等 Tab 中：
- 有知识库时：展示项目画像、目标用户、阶段目标、周计划、预算。
- 无知识库时：显示空状态 + 「关联知识库」按钮（选择/上传 Markdown 或 summary.json）。

#### AI 建议侧边栏（可选折叠）
- 根据项目状态动态生成建议卡片：
  - 「项目已逾期 2 天，建议催促负责人 @张三」
  - 「团队人数不足，建议补充后端开发」
  - 「本周有 3 个任务到期，建议生成同步消息」
- 每条建议提供：查看原因 / 生成草稿 / 确认执行 / 忽略。

## 四、数据层改造（必须先做）

### 4.1 项目状态同步统一按 `project_id`
- 改造 `syncProjectStatus()` 和 `syncAllProjectStatuses()`：
  - 统计需求/任务时以 `project_id` 为主，兼容 `initiation_id`（两者在当前系统里指向同一项目）。
  - 或增加触发器/迁移脚本，保证 `requirement_analyses.project_id` 与 `initiation_id` 一致。

### 4.2 任务变更即时触发项目同步
- 在 `update_dev_task`、`create_dev_task`、`delete_dev_task` 等写操作后，调用 `syncProjectStatus(projectId)`。
- 避免用户改完任务状态后还要手动刷新项目进度。

### 4.3 工作周期与开发任务状态联动
- 员工开始/完成 `work_cycle` 时，若关联了 `dev_tasks.id`，同步更新对应任务状态。
- `dev_tasks` 状态变为 `in_progress`/`done` 时，可反向启停/完成 `work_cycle`（可选，按业务需要）。

### 4.4 成员管理补全
- 后端增加：
  - `DELETE /api/projects/:id/members/:employeeId`
  - `PATCH /api/projects/:id/members/:employeeId`（改角色）
- 前端分配任务时校验负责人是否为项目成员（弱提示或强制）。

### 4.5 风险治理
- 后端增加：
  - `PATCH /api/projects/:id/risk`：修改 `risk_level` + `risk_reason`。
- 前端详情页头部可直接编辑风险等级与原因。

### 4.6 基础信息编辑
- 前端使用已有的 `PATCH /api/projects/:id` 接口，开放编辑：标题、截止日期、团队规模、VP、外部 ID、知识库路径。

## 五、前端改造步骤

### Phase 1：数据层修复 + 列表页增强（1-2 天）
1. 修复 `syncProjectStatus` 按 `project_id` 统计。
2. 任务写操作后即时调用项目同步。
3. 后端增加成员删除/改角色、风险编辑接口。
4. 列表页：
   - 接入 `mine` 过滤。
   - 统计卡片改为真实全量统计。
   - 项目卡片增加风险/同步新鲜度/下一步建议。
   - 新增「只看我的」开关和风险筛选。

### Phase 2：详情页重构（2-3 天）
1. 拆分 `[id]/page.tsx` 为多个子组件：
   - `ProjectHeader.tsx`
   - `ProjectOverviewTab.tsx`
   - `ProjectRequirementsTab.tsx`
   - `ProjectTasksTab.tsx`
   - `ProjectMembersTab.tsx`
   - `ProjectVersionsTab.tsx`
   - `ProjectCloseoutTab.tsx`
2. 重新设计 Tab 结构和默认选中逻辑：
   - 根据 `current_phase` 自动选中最相关 Tab（如 draft → 概览/需求，planning → 需求/任务，executing → 任务/版本，reviewing → 收尾）。
3. 实现基础信息编辑弹窗。
4. 实现成员增删改。
5. 实现风险编辑。

### Phase 3：AI 建议与行动闭环（1-2 天）
1. 在项目详情增加「AI 建议」侧边栏或概览区。
2. 调用 Hermes / Agent 生成项目风险与行动建议。
3. 建议卡片支持：生成通知草稿 / 生成会议邀约 / 生成任务 / 直接执行（需确认）。
4. 列表页增加「AI 风险扫描」入口。

### Phase 4：收尾与归档（0.5-1 天）
1. 收尾 Tab 增加验收 checklist。
2. 增加「归档项目」操作（调用 `transition_project_phase` 到 `archive`）。
3. 归档后项目进入只读模式。

## 七、改造原则

1. **先修数据，再改 UI**：没有一致的数据闭环，前端再漂亮也白搭。
2. **按阶段推进**：不一次性重写所有页面，先做列表+数据修复，再重构详情。
3. **保留已有能力**：PI-ID/RA-ID/DT-ID 链路、阶段状态机、知识库读取等能力继续保留。
4. **为 AI 留位**：所有 AI 写操作都走「建议 → 草稿 → 确认 → 执行」的 stage1 链路。
5. **不 micromanage**：UI 文案和展示以「下一步行动、风险、责任人、deadline」为核心，不堆砌无关细节。

## 八、需要用户拍板的问题

1. **页面名称**：继续叫「我的项目」还是改成「项目作战室」？
2. **入口关系**：是否把「事务中心 → 项目立项」合并进「我的项目」新建流程，避免两个入口？
3. **mine 过滤依据**：当前用户身份如何确定？用 `U9_MY_NAME` / 员工表里的某个字段 / 登录用户？
4. **AI 建议范围**：先做列表页风险扫描，还是先做详情页单项目建议？
5. **工作周期联动**：是否需要任务状态变更自动启停员工工作周期？（改动较大）
